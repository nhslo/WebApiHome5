# Домашняя работа — Модуль 05: Task Manager Client

**CSE5032 · Разработка веб-сервисов · Модуль 05**

Здесь требовалось сделать клиентское MVC-приложение, которое управляет задачами через отдельный Web API. Поэтому запускаются два приложения: сервер API и клиент. Клиент получает именованный `HttpClient` через `IHttpClientFactory`, а сервис отправляет GET, POST, PUT и DELETE. Покажу список, просмотр, создание, редактирование и удаление с подтверждением. Ошибки API отображаются пользователю как понятное сообщение, а не завершают приложение.

---

## Цель

Создать MVC-клиент, который получает и изменяет задачи через отдельное Web API с помощью `HttpClient` и `IHttpClientFactory`.

## Краткий отчёт

В решении находятся два запускаемых проекта: `TaskManagerApi` и `TaskManagerClient`. Клиент использует именованный `HttpClient` `TaskApi`; адрес API берётся из `TaskManagerClient/appsettings.json`. `TaskApiClient` получает настроенный клиент через `IHttpClientFactory` и обрабатывает неуспешные ответы понятными сообщениями.

## Выполнение по шагам

| Шаг по заданию | Реализация | Для чего |
|---|---|---|
| 1. Подготовка | Созданы ASP.NET Core Web API и MVC-клиент в решении | Разделить сервер данных и пользовательский интерфейс |
| 2. Модель | `TaskItem`: `Id`, `Title`, `Description`, `IsCompleted` | Представить задачу и её статус |
| 3. HttpClient | `AddHttpClient("TaskApi", ...)` задаёт `BaseAddress`; `TaskApiClient` получает `IHttpClientFactory` | Не создавать новый `HttpClient` для каждого запроса |
| 4. Список и чтение | Клиент вызывает GET для списка и GET по Id | Показать задачи и детали одной записи |
| 5. Создание | Форма отправляет POST; после успеха открывается список | Добавить задачу через Web API |
| 6. Изменение | Форма загружает задачу, PUT отправляет новые поля и статус | Обновить задачу на сервере |
| 7. Удаление | Страница подтверждения перед отправкой DELETE | Исключить случайное удаление |
| 8. Обработка ответов | Проверяются ответы API; ошибки 400, 404, 500 и соединения преобразуются в сообщения | Не завершать клиент аварийно при ошибках |

## Модель `TaskItem`

| Поле | Тип | Назначение |
|---|---|---|
| `Id` | `int` | Идентификатор задачи |
| `Title` | `string` | Краткое название |
| `Description` | `string` | Описание |
| `IsCompleted` | `bool` | Признак выполнения |

## HTTP-методы

| Действие в клиенте | Метод API | Endpoint | Успешный ответ |
|---|---|---|---|
| Список | `GET` | `/api/tasks` | `200 OK` |
| Детали по Id | `GET` | `/api/tasks/{id}` | `200 OK` |
| Добавление | `POST` | `/api/tasks` | `201 Created` |
| Изменение | `PUT` | `/api/tasks/{id}` | `200 OK` |
| Удаление после подтверждения | `DELETE` | `/api/tasks/{id}` | `204 No Content` |

## Как используется `IHttpClientFactory`

`Program.cs` регистрирует именованный клиент `TaskApi` и его `BaseAddress`. Сервис `TaskApiClient` получает `IHttpClientFactory` через DI и создаёт настроенный клиент методом `CreateClient("TaskApi")`. Повторное создание `HttpClient` непосредственно перед каждым запросом не используется.
